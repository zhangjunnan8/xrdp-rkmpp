# 分阶段计划

> 本文是 `main` 的通用插件计划。`feat/rk3576-direct-mpp` 按用户的新要求改为 RK3576 直接接入，实施入口见 [rk3576/README.md](../rk3576/README.md)，不继续以下通用插件阶段。

每个阶段产生可独立检查的成果。以下为实施顺序，不是已完成的功能列表。

## 阶段 0：项目建立

- [x] 建立独立本地主目录并初始化 `main`。
- [x] 确定 XRDP CodecBridge 项目名和 `xrdp-codecbridge` 仓库名。
- [x] 记录可插拔后端、能力探测、软件回退和多平台适配的设计方向。
- [x] 用户创建 Gitea 仓库并导入本机公钥，SSH 访问验证通过。
- [x] 初始化内容推送至 Gitea，并在 RK3576 检出相同提交。

## 阶段 1：通用接口和软件基线

状态：**2026-10-10 完成**。已实现版本化共享库插件、独立核心、x264 后端、`cb-encode`、故障注入/生命周期/独立解码测试，并验证安装布局。详细范围和环境限制见 [验证记录](validation/2026-10-10-stage1.md)。

实现版本化 C ABI、插件加载、能力查询、帧和包生命周期、错误模型，以及独立编码测试工具。用软件后端或现有软件编码封装验证真实视频输出；测试专用后端只用于注入故障，不冒充可用编码器。

验收：厂商 SDK 缺失时核心仍可构建；能加载独立插件并拒绝不兼容 ABI；输出码流能解码；测试覆盖尺寸/步长、超时、错误和资源释放。软件基线提供后续画质与性能比较数据。

## 阶段 2：Rockchip MPP 独立后端

状态：待开始；阶段 1 的插件 API 和验证工具作为接入基线。

在 RK3576 上实现 NV12 输入、H.264 输出、低延迟参数、关键帧、颜色元数据、缓冲区对齐和超时处理。先验证固定 1080p 单会话，再测重建和设备故障。

验收：输出可持续解码；日志明确报告 MPP 首个成功编码帧；证实设备访问；检查输出画面而不只看进程退出码；反复创建/销毁不出现内存和描述符持续增长。

## 阶段 3：XRDP 接入

以固定上游版本实现小规模适配补丁，在独立测试服务接入 MPP。处理局部更新到完整帧的转换、分辨率变化、重连，以及硬件失败后的软件回退。

验收：Windows mstsc 与 FreeRDP 均能正常连接；测试滚动、文字、窗口拖动、静止画面、断开重连和改变分辨率；指定 MPP 测试时不得静默回退；自动模式能正确恢复软件输出。记录与软件基线的 CPU、编码延迟和画质对比。

## 阶段 4：日常使用验证和部署

补充长时间运行、重复重连、多屏/多会话边界和设备竞争测试；打包插件与适配补丁，提供安装、诊断、升级和回滚说明。

验收：记录明确的测试时长、负载和结果；完成用户实际办公验收；正式切换前保留可用基线与配置备份。只有达到此阶段，才将该组合标为适合日常使用。

## 阶段 5：第二种硬件平台

用户确定具体树莓派或全志型号后，先探测编码能力、驱动 API 和许可条件，选择通用 V4L2 或单独厂商后端。没有硬编码器的设备验证软件回退。

验收：增加后端无需引入厂商依赖到核心；运行共享契约测试和同一套桌面用例；仅将通过实机验证的板卡/系统组合标为支持。

## 后续优化

依据实测瓶颈评估 DMA-BUF、RGA 色彩转换、GPU 渲染及 AVC444。每项优化都需要证明它改善目标场景，并验证新的缓冲区所有权、同步和码流兼容性。
